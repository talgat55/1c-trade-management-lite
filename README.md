# 1C Trade Management Lite

Небольшая конфигурация на платформе **1С:Предприятие 8.3** для учета поступлений, продаж и остатков товаров.

Проект сделан как портфолио-проект для демонстрации базовых навыков разработки на 1С:
- работа со справочниками и документами;
- движения по регистру накопления;
- проведение документов;
- проверки перед проведением;
- управляемые формы;
- запросы;
- отчеты на СКД.

## Функциональность

### Справочники

#### Товары
Хранение номенклатуры товаров.

#### Клиенты
Хранение данных о клиентах.

## Документы

### Поступление

Документ фиксирует поступление товаров на склад.

Возможности:
- добавление товаров;
- указание количества и цены;
- расчет суммы строки;
- расчет итоговой суммы документа;
- проверка корректности данных перед проведением;
- формирование приходных движений по регистру `ОстаткиТоваров`.

При проведении количество товара увеличивается.

### Продажа

Документ фиксирует продажу товаров клиенту.

Возможности:
- выбор клиента;
- добавление товаров;
- автоматический расчет суммы строки;
- автоматический расчет итоговой суммы;
- проверка остатков перед проведением;
- запрет продажи товара при недостаточном остатке;
- проверка корректности строк документа;
- формирование расходных движений по регистру `ОстаткиТоваров`.

При проведении количество товара уменьшается.

## Учет остатков

Для учета количества товаров используется регистр накопления:

`ОстаткиТоваров`

Основные данные регистра:
- Товар
- Количество

Документ `Поступление` создает движение `Приход`.

Документ `Продажа` создает движение `Расход`.

Перед проведением продажи выполняется проверка доступного остатка товара.

## Отчеты

### Остатки товаров

Отчет построен на системе компоновки данных.

Показывает текущие остатки товаров:

| Товар | Остаток |
|---|---:|
| Тестовый товар | 19 |

Источник данных:

`РегистрНакопления.ОстаткиТоваров.Остатки()`

### Продажи по клиентам

Отчет показывает сумму проведенных продаж в разрезе клиентов.

| Клиент | Сумма продаж |
|---|---:|
| Клиент 1 | 15000 |

В отчете используются:
- запрос;
- группировка по клиенту;
- агрегатная функция `СУММА`;
- СКД.

## Бизнес-сценарий

Пример работы системы:

1. Пользователь создает товар.
2. Создается документ `Поступление`.
3. Товар поступает на склад.
4. В отчете `Остатки товаров` отображается доступное количество.
5. Создается документ `Продажа`.
6. Перед проведением система проверяет остаток.
7. После продажи остаток уменьшается.
8. Продажа отображается в отчете `Продажи по клиентам`.

## Проверки данных

Перед проведением документов выполняются проверки:

- табличная часть не должна быть пустой;
- товар должен быть выбран;
- количество должно быть больше нуля;
- цена не может быть отрицательной;
- для продажи должен быть выбран клиент;
- продажа запрещается при недостаточном остатке товара.
